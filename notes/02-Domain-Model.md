# Domain Model

## System Overview

The AI Fault Detection System continuously monitors an electrical distribution network through telemetry data collected from sensors installed on power poles.

Incoming telemetry is analyzed to identify abnormal electrical behavior such as voltage drops, current spikes, communication failures, or complete power loss.

When abnormal conditions are detected, the system identifies the most probable fault location, creates an incident, and provides actionable information to operators.

The domain model describes the real-world entities involved in this process and the relationships between them.

---

## Business Problem

Electrical distribution networks generate continuous streams of telemetry from thousands of sensors.

Operators cannot manually inspect every telemetry event.

The system must automatically:

- Receive telemetry
- Detect abnormal conditions
- Identify the probable fault location
- Generate incidents
- Maintain historical records

---

## Core Entities

### Pole

Represents a physical electrical pole within the distribution network.

Each pole has:

- unique identifier
- geographic location
- operational status
- installation details

---

### Sensor

Represents a monitoring device attached to a pole.

A sensor continuously reports electrical measurements.

Each sensor belongs to exactly one pole.

---

### Telemetry

Represents one observation reported by a sensor.

Examples include:

- voltage
- current
- temperature
- signal strength
- timestamp

Telemetry forms the primary input to the fault detection engine.

---

### Incident

Represents a detected abnormal condition requiring investigation.

Each incident contains:

- detected fault
- severity
- probable pole
- creation time
- current status

---

### Fault

Represents the classification of an abnormal condition.

Examples:

- Voltage Drop
- Over Current
- Communication Failure
- Power Loss

A fault type defines how the incident should be interpreted.

---

## Relationships

A Pole contains one or more Sensors.

A Sensor produces many Telemetry records.

Telemetry may trigger a Fault Detection.

A detected Fault creates one Incident.

Each Incident references the Pole most likely responsible for the abnormal condition.

---

## Business Rules

Each sensor belongs to exactly one pole.

A telemetry record cannot exist without a sensor.

Every incident must reference one detected fault.

Incidents remain in the system even after resolution to preserve historical analysis.

Telemetry data is immutable after storage.

---

## Assumptions

Every pole contains at least one sensor.

Telemetry timestamps are generated by the sensor.

Fault localization identifies a single most probable pole.

Historical telemetry is retained for future analysis.

---

## Future Expansion

The domain model can later support:

- maintenance scheduling
- technician assignment
- outage prediction
- AI confidence scoring
- multiple sensor types
- real-time dashboards
